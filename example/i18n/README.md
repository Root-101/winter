# i18n Example

Answers in the language of each request (`Accept-Language`), with typed translations generated by
[slang](https://pub.dev/packages/slang) from YAML files. No function is passed around: any code
(a validator, a service, a handler) reads the language of the request in progress with
`requestLocale`, and concurrent requests never mix their languages.

## How it works

1. **The texts** live in `lib/i18n/en.i18n.yaml` (base locale, declares the parameter types such as
   `{id: int}`) and `lib/i18n/es.i18n.yaml`.
2. **The generation**: `slang.yaml` configures slang (`locale_handling: false`: no global state).
   After changing a YAML file, regenerate the code and commit it:
   ```bash
   dart run slang
   ```
   It writes `lib/i18n/messages.g.dart`, `messages_en.g.dart` and `messages_es.g.dart`.
3. **The getter `t`** (`lib/i18n/t.dart`) returns the messages in the language of the request:
   ```dart
   AppMessages get t => _cache[AppLocaleUtils.parseLocaleParts(
     languageCode: requestLocale.languageCode,
     countryCode: requestLocale.countryCode,
   )]!;
   ```
   It must be a **getter**, never a `final`: a `final` would keep the language of the first use.
4. **The languages** of the app are configured once (`I18nServer.configure`):
   ```dart
   Winter.context.setUp(
     localeConfig: LocaleConfig(supported: [WinterLocale.english, WinterLocale.spanish]),
   );
   ```

## Where `t` is used

- **Validator with a text of the app**: `notBlank(message: t.orders.productRequired)` in
  `OrderRequest.validate()`. The built-in texts of Winter (`notNull`, `min`...) are translated too,
  so a 422 mixes both, all in the same language.
- **Service**: `OrderService.find` throws `NotFoundException(detail: t.orders.notFound(id: id))`
  without receiving the request.
- **Handler**: `t.greetings.hello(name: requestAuthentication!.name)` uses both the language and
  the user of the request.

Every response whose code read the language (`t`, `requestLocale` or `request.locale`) gets
`Vary: Accept-Language` automatically, so caches keep one copy per language. A response that never
reads it (e.g. `GET /orders/1` when the order exists) does not vary.

## Routes

* `GET /hello` (header `X-User` required): `Hello, adam` / `Hola, adam`.
* `POST /orders` `{"product": "book", "quantity": 2}`: `201 {"id": 1, "message": "Pedido 1 creado"}`,
  or a 422 with the validation errors.
* `GET /orders/{id}`: the order, or a 404 `Pedido 7 no encontrado`.

```bash
dart run lib/main.dart
curl -H 'Accept-Language: es' localhost:8080/orders/7          # Pedido 7 no encontrado
curl -H 'X-User: adam' -H 'Accept-Language: es-MX' localhost:8080/hello   # Hola, adam
```

## Tests

`test/i18n_test.dart` runs the whole pipeline in memory with `WinterTestClient` (no port). To test
code that uses `t` outside the server, give it a language with
`RequestScope.run(RequestScope(locale: WinterLocale.spanish), () => ...)`.
