# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`winter` is an experimental, Spring-inspired backend framework for Dart built directly on `dart:io` (it ran on `shelf` until phase 3.1; it no longer depends on it).
It is a pure Dart package (no Flutter), SDK `^3.13.0`. `ROADMAP.md` tracks the planned work, `DECISIONS.md` the current design decisions (only the final decision and why, no history), and `doc/` has a guide per module.

Before any release, run the whole *Release review* of `ROADMAP.md` (roadmap, API, security, tests without overlaps, examples, docs, checks) and record what it found there.

## Commands

The code needs Dart >= 3.12 because it uses private named parameters such as `{this._cors}`. Run everything through FVM. `.fvmrc` pins Flutter 3.47.1, which ships Dart 3.13. Prefix each command below with `fvm` (`fvm dart test`).

```bash
dart pub get
dart analyze                     # lints: package:lints/recommended + rules in analysis_options.yaml
dart format .
dart test                        # all tests
dart test test/server/router/basic_routing_test.dart        # single file
dart test test/security/cors_test.dart -N "name substring"  # single test by name
dart test --coverage-path=coverage/lcov.info --branch-coverage   # coverage (lcov)
dart run benchmark/router_benchmark.dart   # in-process routing benchmark (also server_*_benchmark.dart)
```

`example/` has one package per topic (`routing`, `bodies`, `validation`, `object_mapper`, `errors`, `filters`, `security`, `di`, `api_patterns`, `openapi`, `realtime`, `scheduling`, `i18n`) with one file per case (`lib/<case>.dart` with a `router()` and a `main`, its `test/<case>_test.dart` in memory, a row in the README of the topic), and complete apps in `example/apps/` (`auth_jwt`, `orders`, `files_gallery`, `production`). Each is a standalone package that depends on the framework by path (`../../`, `../../../` for the apps). Run them from inside their own folder (`dart pub get`, `dart run lib/<case>.dart` or `lib/main.dart`, `dart test`). A new feature gets a small case in its topic; a test that needs a real server (WebSockets) uses its own port.

Lint and analyzer rules that affect how code must be written:
- `strict-casts` and `strict-inference` are on. Cast `dynamic` values explicitly, for example `jsonDecode(...) as List` or `json['id'] as String`, and give explicit type arguments such as `Future<void>.delayed`.
- Single quotes, required trailing commas, `const` constructors, required named params first, and no `print` (use `stdout.writeln`).
- No imports from another package's `src/` (`implementation_imports`).
- Every public member needs a dartdoc (`public_member_api_docs`; off for `example/` in `example/analysis_options.yaml`), and every public top-level declaration ends its doc with `/// {@category X}`, X one of the categories of `dartdoc_options.yaml` (one per module). `fvm dart doc --dry-run` must report no warnings.

The HTTP constants are `HttpHeader` (`static const`), `StatusCode` (one enum: `value`, `series`, `reasonPhrase`, getters `isSuccessful`/`isError`..., `resolve`/`valueOf`), `HttpMethod` and `MediaType`. They were renamed so they don't shadow the `HttpHeaders` and `HttpStatus` classes of `dart:io`; don't bring the old names back.

## Architecture

**Single public entry point.** All code lives in `lib/src/`. `lib/winter.dart` is the only public library: it re-exports each module's barrel file, hiding the internal helpers with `export ... hide` (`addVary`, `limitBodySize`, `writeResponse`, `requestFromHttpRequest`, the router helpers; `utils/` and `winter_messages.dart` are not exported at all; see `DECISIONS.md` §11). Library code that needs a hidden helper imports its `package:winter/src/...` file with `show`. Library code imports `package:winter/winter.dart` instead of relative files. New public files have to be added to their module's barrel file (`src/router/router.dart`, `src/context/context.dart`, `src/security/security.dart`, `src/filter_chain/filter.dart`, `src/http/http.dart`, `src/utils/utils.dart`). Internal helpers are left out of the barrels and imported by their `package:winter/src/...` path. For example, `src/router/path_template.dart` compiles and caches the regex of each route path, and both `Route.match` and path-param extraction use it.

**Global static state.** `Winter` (`lib/winter_server.dart`) holds one static `WinterContext` and at most one running server:
- `WinterContext` (`lib/src/winter_context.dart`) holds the `ObjectMapper`, `ExceptionHandler`, `DependencyInjection` and `Env` (decisions in `DECISIONS.md` §6, guide in `doc/configuration.md`: `find<T>` returns `T?`, `require<T>` a `T`, `requireAll` names every missing variable, types come from the `_parsers` table (scalars, nullables and lists), a `String` is never trimmed, and errors never include a value; `Env.load()` reads `.env`/`.env.<WINTER_PROFILE>` under the process variables, ignoring missing files). It exists before the server starts, and you can replace it with `Winter.start(context: ...)` or `Winter.context.setUp(...)`.
- Top-level getters `di`, `om`, `eh`, `env` and `logger` are shortcuts into `Winter.context` and are used throughout the codebase.
- Logging (decisions in `DECISIONS.md` §7, guide in `doc/logging.md`): framework code never writes to `stdout` or `stderr` directly; it always goes through `logger` (`WinterLogger`, default `ConsoleLogger(minLevel: LogLevel.info)`; `JsonLogger` for production). `log(level, message, {error, stackTrace, fields})`; check `logger.isEnabled(LogLevel.debug)` before building a debug message (the rate limiter does, so an attack doesn't cost a string per rejected request). Never log a body, a query string, a token, or the message of a deserialization error (it may contain the value sent). Every request has an id (`RequestScope.requestId`, top-level `requestId`): the `X-Request-Id` of the request if `isValidRequestId`, or a new UUID; `_handleRunRequest` adds it to every response, the loggers include it, and `internalServerErrorResponse()` puts it in the 500. `_checkHeaders` (inside the request zone, right after the pipeline) turns a response with a header `dart:io` would refuse (CR/LF or another control character, non-ASCII, a name that isn't a token) into a 500 and logs it without the value.
- `Winter.start(...)` resolves each of `ServerConfig`, the router and `SecurityConfig` in this order: explicit argument, then `di.tryFind<T>()`, then the default. It then `di.put`s the result. `ServerConfig` is `const` (`host` String, `port`, `shared`...), `ServerConfig.fromEnv` reads `PORT`/`HOST`, and `Winter.start` calls `config.validate()` before registering anything or opening the port. `ServerConfig.maxBodySize` (default 10 MB, `null` for no limit) wraps the request body stream with `limitBodySize`. `ServerConfig.requestTimeout` (default `null`) adds `_RequestTimeoutFilter` (order -98, after CORS and the security headers) that answers a 503 when the chain takes longer; the abandoned handler goes on and a late error is logged. Its tests run in a `Zone` whose timers fire at once (`test/server/request_timeout_test.dart`), never on the real clock. Reading a body over the limit throws `PayloadTooLargeException` (413); a body nobody reads is never rejected. A body that stops being read before its end (a 413, a malformed multipart) is read to the end and discarded (`_discardedOnCancel` in `requestFromHttpRequest`), never cancelled: cancelling the body of `dart:io` closes the connection without the answer. `Winter.close()` (or a failed start) restores the previous value of those three registrations, so they don't carry over to the next server. Starting a second server throws. Tests must call `Winter.close(force: true)` in `tearDownAll`.

**Graceful shutdown.** With `ServerConfig.handleSignals` (on by default), SIGINT/SIGTERM call `Winter.shutdown()`. It closes the server and waits for the in-flight requests, up to `shutdownTimeout`, then calls `onShutdown`. A second signal forces the close. `HttpServer.close()` from `dart:io` does NOT wait for in-flight requests, which is why `_buildHandler` counts them in `_InFlightRequests`. Never `await` a second `HttpServer.close(force: true)`: its future never completes. The framework never calls `exit()`.

**Request pipeline** (`Winter.buildHandler` → `Winter._handleRunRequest`; `Winter.start` serves this same handler, and `WinterTestClient` calls it in memory without a port):
1. `Winter.start` binds an `HttpServer` (`bindSecure` with `ServerConfig.securityContext`; `autoCompress`, `idleTimeout`, no `Server` header, default headers cleared) and `_serve` turns each `HttpRequest` into a `RequestEntity` (`RequestEntity.fromHttpRequest`, headers read as a view of `dart:io`'s, no copy), runs the `RequestHandler` of `buildHandler`, and writes the result with `writeResponse` (in `response_entity.dart`: `Date` cached per second, `Content-Length` for bytes written with `add`, chunked + `bufferOutput: false` for a stream, no body for HEAD/204/304, length left out when gzipping; a failure while writing is logged at debug). `RequestEntity`/`ResponseEntity` are Winter's own types (decisions in `DECISIONS.md` §10, guide in `doc/requests-and-responses.md`): `headers` (one value, a view) and `headersAll` (every value, case insensitive, built by `src/http/headers.dart`), `cookies`, read-only params, a body read once and shared by copies, and a single synchronous `copyWith` (headers added, `null` removes). Handlers receive a `RequestEntity` and return a `ResponseEntity`.
2. `router.resolveRoute(request)` returns the matched `Route`; the server attaches it to the request (`attachRoute`, internal: `request.route`, path params computed from it) and the chain ends in `route.handler`. Without a route the router's `handler` answers (404/405/`OPTIONS`, or a `ServeRouter`). `WinterRouter` returns its matched route, `MultiRouter` delegates to the same inner router its `handler` will use, and the default (for example `ServeRouter`) is `null`. A custom router that holds routes or wraps other routers must override `resolveRoute`, or its route filters (including `AuthFilter`) are silently skipped.
3. A `FilterChain` is built from the global filters followed by the route filters, sorted by `Filter.order`, with the router's handler as the final link. Filters call `chain.doFilter(request)` to continue, or return a response to short-circuit. `shouldFilter` skips a filter.
4. `CorsFilter` is prepended automatically when `SecurityConfig.cors()` returns non-null.
5. The server passes `eh` to the chain as its `exceptionHandler` (default `SimpleExceptionHandler`; decisions in `DECISIONS.md` §4, guide in `doc/error-handling.md`). `ExceptionHandler.call` receives `Object`: anything thrown by a filter or the handler, `Exception` or `Error`, is turned into a response where it's thrown, so every outer filter (CORS, logs) receives a response and a filter's `catch` around `chain.doFilter` never fires. Every error is a `ProblemDetails` (`application/problem+json`: `type`, `title` = reason phrase, `status`, `detail` only when there is one; the 422 adds `violations`). `ApiException(status, detail:, type:, title:, extensions:, headers:)` and its shortcuts (`NotFoundException`...) map to their status; `DeserializationException` is a 400 with its message as `detail`; `ResponseException` answers its own response as is; anything else is logged through `logUnhandledError` and becomes a generic 500 without details. The errors of Winter are exceptions too: the router throws `NotFoundException`/`MethodNotAllowedException` (`methodNotAllowedOrNotFound` returns `Never`), `AuthFilter` throws 401/403, `RateLimiterFilter` throws `TooManyRequestsException`. `SimpleExceptionHandler..on<T>(fn)` maps an exception (most specific type wins); override `handle` to change the default rules. A `FilterChain` built without an `exceptionHandler`, as in the unit tests, rethrows: tests that call a filter directly must expect the exception. Errors outside the chain (routing) go to `eh` in `_runPipeline`; if `eh` throws, both errors are logged and the answer is a generic 500.

**Routers** (`lib/router/`, decisions in `DECISIONS.md` §9, guides in `doc/routing.md` and `doc/filters.md`): `BaseRouter` has `canHandle` and `handler`. `ServeRouter` is a single catch-all function. `WinterRouter.handler` is only reached by the server when no route matched; called directly it routes the request itself. `WinterRouter` takes nested `Route`s (for example `Route.parent`) and flattens them at construction time, joining paths and inheriting parent filter configs. Its `routes` are read-only (`UnmodifiableListView`); `addRoute` is the only way to add one, with the same rules as the constructor. When flattening, a generated route key is recomputed from the full path, so sibling children with the same relative path don't collide. A generated key is `METHOD /full/path` (`PARENT /users` for a parent; no hash, no `crypto`); a custom `key:` is kept as is (filters use it through `request.route?.key`). A route is a duplicate if it has the same key, or the same method and shape (`Route._shape`: param names ignored, their regex kept). `RouterConfig` fails (`StateError`) on an invalid or duplicated route by default; `Default*.ignore()` drops it with a warning. `isValidUri` validates only the literal parts (params and regex characters can be anything). It supports regex paths; a param regex can't contain `{}`. When several routes match, a static route (no `{param}` and no regex, see `Route.isStatic`) wins. Among the rest, the first one declared wins. Path params are URL-decoded; `request.pathParam<T>(name)` / `queryParam<T>(name, values:)` parse `String`/`int`/`double`/`num`/`bool`/`DateTime`/one of `values`, and an invalid value is a `BadRequestException` naming the param (never the value). Paths are normalized: a trailing slash is ignored (`/users/` matches `/users`, except the root `/`); repeated slashes are not joined (`//users` is a 404; the router matches `requestedUri.path`). A lone `.` in a path is a literal dot; only `.*`, `.+`, `.?` and `.{n}` act as regex. A HEAD request with no HEAD route falls back to the GET route, `dart:io` drops the body, and `Allow` lists HEAD whenever it lists GET, and OPTIONS whenever the path exists. When no route matches, `noRouteResponse` answers an OPTIONS with a 204 + `Allow`, a 405 with `Allow` if the path exists for other methods, and a 404 otherwise (`MultiRouter` merges `allowedMethods` from its inner `routers`). `Route.static(path:, directory:)` is a GET route with the regex param `staticFile` that serves files through `StaticFiles` (`src/router/static_files.dart`): forbidden segments (`..`, hidden, `\`, `:`) and a canonical-path check against links, strong `ETag` + `Last-Modified`, 304, a single `Range` (206/416, `If-Range`), index with a 308 to the trailing `/`, a MIME table extended by `mimeTypes:`. A route path is never cut at `?` (it belongs to a regex). `Route.health(path:, checks:, timeout:)` is a GET route (`src/router/health.dart`, `healthHandler` hidden): named `HealthCheck`s (`FutureOr<bool>`) run at once with a timeout each, 200 `UP` or 503 `DOWN` with the state of each (the reason only logged), `application/json` (not problem+json) and `Cache-Control: no-store`. `RouterConfig` has three hooks, `onInvalidUrl`, `onDuplicatedRoute` and `onLoadedRoutes`, each with `Default*` implementations. `FilterConfig` is immutable (`merge`, no `add`).

**OpenAPI** (`lib/src/openapi/`, decisions in `DECISIONS.md` §12, guide in `doc/openapi.md`): `Route` has `docs` (`RouteDocs`: summary, tags inherited by the children of a parent with docs, status, request/response/responses, query, hidden; `RouteDocs.none`); `Route.static`/`Route.websocket` default to hidden, `Route.health` documents itself. `OpenApi(...).toJson()` (`_OpenApiBuilder`) walks the router (`MultiRouter` too), turns each route into an operation (path params typed from their regex, security and 429 from the filters whose `shouldFilter` passes for a synthetic request with the route attached, Problem Details components), and a body (example, `JsonSchema`, `BodyDocs`) into a schema: `JsonSchema.fromExample(om.serialize(example))` plus `withRules(validationRulesOf(model), om)`. `validationRulesOf` (hidden, in `validation.dart`) runs `validate()` with a `Zone` flag that makes `addRule` record every rule without evaluating it; `pattern()` puts its regex in `params`. A `Map` example is taken as is (JSON names). `Route.openApi`/`Route.swaggerUi` (hidden helpers `openApiHandler`/`swaggerUiHandler`) serve the document (built by the first request) and a Swagger UI page from unpkg at a pinned version.

**Scheduled tasks** (`lib/src/scheduling/`, decisions in `DECISIONS.md` §13, guide in `doc/scheduling.md`): `Schedule` (`next(after)`; `Schedule.every`, `Schedule.cron` = `CronSchedule.parse`, 5 fields as boolean tables, dom/dow OR when both are restricted (a field starting with `*` counts as unrestricted), walked in UTC fields and built local or UTC). `Scheduler` (`every`/`cron`/`schedule` with a unique `name`, `start`/`stop(timeout:)`, `clock:`) holds `ScheduledTask`s: one `Timer` each that waits `_maxWait` (1 minute) at most and rechecks the clock; a due run is `run()` (skipped while running unless `allowOverlap`; missed runs are not repeated, only logged), executed in a new `RequestScope` (completed after the task), errors logged. `Winter.start(scheduler:)` resolves it (argument, `di`, none), registers it restorably, starts it after the port is open; `close` stops it and waits for its runs with the same timeout as the requests (`force`: not waited). Tests fake the timers in a `Zone` (`test/scheduling/fake_time.dart`) and the clock with `clock:`; the server tests use ports 9311/9312.

**WebSockets** (`lib/src/websocket.dart`): `Route.websocket(path:, handler:, allowedOrigins:, protocols:, pingInterval:)` is a GET route whose handler (`webSocketRouteHandler`, hidden) throws a 426 for a non-handshake and a 403 for a disallowed `Origin`, and otherwise returns a 101 `ResponseEntity` with a `WebSocketUpgrade` in its context (`webSocketUpgradeKey`, hidden). `_serve` recognizes it before `writeResponse` and calls `_upgrade`: `WebSocketTransformer.upgrade`, the handler run unawaited inside a new `RequestScope` (completed on `socket.done`), errors logged and closed with 1011. `_WebSockets` tracks the open sockets; `Winter.close` closes them with 1001, and one that finishes its upgrade while closing is closed at once. Tests need the real server (`test/server/websocket_test.dart`, port 9112) and must listen to the client socket for `done` to complete.

**Server-Sent Events** (`lib/src/server_sent_events.dart`): `ResponseEntity.sse(Stream<ServerSentEvent>, keepAlive:)` is a static that builds a stream response through `serverSentEventsBody` (hidden): a `:` comment first, one every `keepAlive` without events (a periodic `Timer`; tests override `createPeriodicTimer` in a `Zone`), the subscription to the app's stream cancelled when the client leaves, and the end when the server starts closing (`serverClosing`, hidden, a `Completer` completed at the start of `Winter.close`; never without a server). `ServerSentEvent` rejects line breaks in `event`/`id`.

**Other modules:**
- `context/object_mapper` (decisions in `DECISIONS.md` §2): `serialize`/`deserialize` work with JSON values, `encode`/`decode` with JSON text. Primitives, `List`/`Map`/`Iterable` are kept as they are (recursively). Any other object is converted with, in order: a `Serializer` of the exact `runtimeType`, the first `Serializer` of a supertype, a `toJson()` called dynamically (no interface; checked as a tear-off first, so an error inside `toJson` is never taken as a missing one), and enum `name`; otherwise `MissingSerializerError` (500). Which rule applies is cached per `runtimeType` (`_converters`, cleared when the serializers change). `encode` is a single pass (`JsonEncoder` with `toEncodable`) and must stay equal to `jsonEncode(serialize(x))`; `encodeBytes` (`JsonUtf8Encoder`, what `ResponseEntity` uses for UTF-8) must stay equal to `utf8.encode(encode(x))`, and `decodeBytes` (a fused UTF-8 + JSON decoder, what `body<T>()` uses for UTF-8 on the cached bytes) to `decode(utf8.decode(bytes))`; measure changes with `benchmark/object_mapper_benchmark.dart`. `DateTime` is always UTC. Deserializers are looked up by exact `Type`, never by name: registering `Deserializer<T>` also derives `T?`, `List<T>`, `Set<T>`, `Map<String, T>` (and their nullable forms); deeper types are registered with `om.deserializerOf<T>().list()`/`.set()`/`.map()`/`.nullable()`, and maps with other keys with `.mapWithKeys<K>()` (`int`/`double`/`num`/`bool` parsed from the key, any other `K` through its own deserializer with the key as a string). `JsonAdapter<T>` (`.string`/`.integer`/`.number`/`.json`/`.value`, `adapters:` or `addAdapter`) registers a `Serializer` and a `Deserializer` in one; it's not called `JsonConverter` to avoid clashing with `json_annotation`. `TestResponse.as<T>({objectMapper})` decodes a test response through the mapper. A hand-written `fromJson` reads typed fields with the `JsonObjectFields` extension on `Map<String, dynamic>`: `json.field<T>(dartName)` (deserialized by the mapper running `Deserializer.json`, `ObjectMapper._current`, or `om`; a missing non-nullable field is `missing`) `json.object(name, fromJson)` and `json.patch<T>(name)` (a `PatchValue<T>`: absent, or present with a value that may be `null`, for PATCH); their errors carry the JSON name of the field in the path. The mapper tracks the types the app registered (`_appSerializers`/`_appDeserializers`, not the defaults); `WinterContext.setUp(objectMapper:)` logs a warning with those the new mapper lacks (`lostRegistrations`, hidden). Besides `Deserializer<T>(fn)` and `.json(fromJson)`, the typed constructors `.string`/`.integer`/`.number`/`.boolean` check the JSON type first, and enums are read with `Deserializer<E>.enumByName(E.values)` (they are written by `name` without registering anything). Primitives are strict (`"12"` is not an `int`, `12.0` is). A failed deserialization is a `DeserializationException` (400) whose message is `path: reason` (`$.items[1]: expected a string, got an integer`) and never contains Dart details nor type names; the original error is in `cause`. A missing deserializer is `MissingDeserializerError` (500). Options: `includeNulls`, `fieldNaming`, `durationFormat`, `rejectUnknownFields` (off by default; `Deserializer.json(..., rejectUnknownFields:)` overrides it per type; the `fromJson` receives a `_ReadKeys` map that records the keys read, and a key never read is `$.key: unknown field`), `prettyPrint` (on by default: the responses are indented, so tests must compare decoded JSON, not the text); the first two only touch objects (`toJson()`/serializer results and the map given to `Deserializer.json`), never a `Map` used directly. `ProblemDetails` and `ConstraintViolation` are never renamed (the error format has fixed names, `DECISIONS.md` §4), though the value of `fieldName` follows `fieldNaming`. A text body of a `ResponseEntity` always has `; charset=<its encoding>` in its `Content-Type` (`_resolve`); a `Uint8List` body is bytes, a `List<int>` is JSON. `RequestEntity.body<T>({objectMapper})` decodes through `om` (or the given mapper): a `Content-Type` other than JSON, `+json`, `text/plain` or none is a 415, and `body<String>()` only decodes when the body is JSON. It caches the raw body string, so you can call it many times and with different `T`, but after the first call `read()` and `readAsString()` fail because the stream has already been consumed. `request.bytes()` (and `body<Uint8List>()`) gives the whole body as bytes from the same cache, whatever the `Content-Type`; `body<String>()` reads any non-JSON body as text, and bytes that aren't text in the charset are a 400 (`readAsString()` too). `request.formData()` reads an `application/x-www-form-urlencoded` or `multipart/form-data` body from the same cache (any other `Content-Type` is a 415, a malformed body a 400) into a `FormData` (`fields`, `fieldsAll`, `field<T>()` parsed by the same `_parseParam` as `queryParam<T>`, and `files`/`filesAll` of `UploadedFile`). `request.multipart()` streams the parts (`MultipartPart`, `lib/src/multipart.dart`) with Winter's own parser (not `package:mime`, see `DECISIONS.md` §10): it pulls the body with a `StreamIterator`, so an error is thrown by the read waiting for it and never hangs; a part not read before the next one is discarded. `parseMultipart`/`multipartBoundary` are hidden from the export. The generic type argument of a `Serializer`/`Deserializer` must be given explicitly: one created as `dynamic` or `Enum` (what Dart infers inside a `List<Deserializer>`) throws an `ArgumentError` (`_MapperEntity`).
- `filter_chain/default_filters.dart`: `LoggingFilter` logs `REQUEST: METHOD /path` and `RESPONSE: METHOD /path => status (ms)`. It never logs the body or the query string, which can contain tokens or personal data. `logResponse` receives the request, the response and the duration, and gets error responses too.
- `RequestEntity.clientIp({trustedProxies})` returns the connection address. It ignores `X-Forwarded-For` unless `trustedProxies > 0`, because that header can be spoofed. `RateLimiterFilter` uses it by default. `change()` is implemented for both entities and returns the Winter type. When the body was already read, `RequestEntity.change` reuses the cached raw body.
- `context/validation` (decisions in `DECISIONS.md` §3, guide in `doc/validation.md`): `Validatable` is an `abstract interface class`; its `validate()` builds a `ConstraintValidatorContext` and calls `cvc.field(name, value)`, which returns a `FieldValidator<T>` whose rules run as they are chained. The validators are generic extensions with a bound (`StringValidators<T extends String?> on FieldValidator<T>`, and the same for `num?`, `Iterable<Object?>?`, `Map<Object?, Object?>?`, `DateTime?`, `Validatable?` (`valid()`), `Iterable<Validatable?>?` and `Map<String, Validatable?>?` (`validEach()`, a map key quoted as in JSON: `prices["eur"]`, never renamed by `om.jsonFieldName`)) that return `FieldValidator<T>`, so the type of the value decides which exist and is kept along the chain; a new validator must follow that shape; `CommonValidators<T>` (`notNull`, `custom`, `oneOf`, `isEnum`) apply to any type. Every validator except `notNull` passes on `null`. A new validator calls `addRule(isValid, message: () => ..., code:, params:)`; the message is a function so a valid request never reads `requestLocale` (no `Vary`). Each `ConstraintViolation` has `code` (the key of the text in `*.i18n.yaml`) and `params`; its JSON never has the `value`, and a `sensitive` field never stores it. `body<T>()` validates a `Validatable` body (or a list or a map of them) unless `validate: false`, and then, only if that passed, runs `AsyncValidatable.validateAsync()` (same shapes; `cvc.check(name, isValid, message: () => ...)` adds an async rule), and a failure throws `ValidationException` (422). The exception handler converts each `fieldName` with `om.jsonFieldName` (it follows `fieldNaming`), and `params` must only hold JSON values. The date validators use `ConstraintValidatorContext.clock`, which nested objects inherit through a `Zone`.
- `security/` (decisions in `DECISIONS.md` §8, guide in `doc/security.md`): the app authenticates with its own filter (`request.securityContext.setAuthentication(...)`); `Authentication` has only `roles` and `permissions`. `AuthFilter` throws a 401 with `WWW-Authenticate` (`challenge`, `Bearer`) or a 403. Rules (`hasRole`, `hasPermission`, `rule(fn, describe:)`, `&`/`|`) receive `evaluate(authentication, request)`; a custom rule overrides `describe()`, not `toString()`. `requestPrincipal<T>()`/`request.principal<T>()` give the user (401 for nobody, `StateError` for a wrong type). Every response gets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` and `X-Request-Id` in `_handleRunRequest` (the `dart:io` default headers are cleared, so the real server and `WinterTestClient` match); `SecurityConfig.securityHeaders` adds `SecurityHeadersFilter` (order -99, after CORS at -100). `CorsFilter` warns about `'*'` with credentials, adds `Vary: Origin` whenever the answer depends on the origin, and always exposes `X-Request-Id`. `RateLimiter` is async (`check`/`peek`/`reset`/`clear`) over a `RateLimiterStore` (default `InMemoryRateLimiterStore`, which purges inactive ids once per window).
- `request_scope.dart`: `_handleRunRequest` runs each request inside its own `Zone` holding a `RequestScope`, so any code can read `requestAuthentication` / `requestSecurityContext` / `requestLocale` without receiving the request, and concurrent requests never mix. `requestLocale` is `request.locale`, computed when the scope is created (outside a request: `localeConfig.fallback`). Reading either one inside a request sets `scope.localeRead`, and `_handleRunRequest` then adds `Vary: Accept-Language` with `addVary` (only if `localeConfig.supported` has more than one language); don't add it by hand. `RequestScope.onComplete(callback)` runs code when the request ends (after the response is built, before it's sent); `_handleRunRequest` calls `scope.complete()` in a `finally` inside the zone. The security context is created eagerly before the chain, so `request.securityContext`, its `copyWith()` copies and the scope share the same object. Extensions of the request store data in `request.context`, a `ContextMap` keyed by typed `ContextKey<T>` objects (security and locale use it; the route is a field). Outside a request they are `null`; `RequestScope.run` gives a scope to code outside the server (tests).
- `context/dependency_injection` (decisions in `DECISIONS.md` §5, guide in `doc/dependency-injection.md`): a service locator keyed by `(Type, tag)`, where the type is normalized to its nullable form (`T` and `T?` are the same key); lookups are by exact type, never by supertype. `put` (an instance), `putLazy` (created by the first `find`; `_creating` detects cycles), `putFactory` (new per `find`) and `putScoped` (one per request, kept in an `Expando` keyed by the `RequestScope`, disposed through `RequestScope.onComplete`; finding it while a lazy one is being created is a `StateError` (captive dependency), and so is finding it after `RequestScope.isCompleted`). `put`/`putLazy`/`putScoped` take `onDispose`; `child()` returns a container whose `parent` is this one: its own registrations win, and a missing key comes from the parent; a parent's `putLazy` is copied into the child without its instance on the first find (so it's built with the child's fakes and the parent never changes), while `put` instances are shared and factories/scoped ones resolve in the child. `registrations`, `delete`, `createAll` and `disposeAll` only see the container's own entries. `putLazyAsync` registers an async singleton (`DependencyKind.lazyAsync`): `ready()` creates them in registration order (failures collected like `createAll`; a child also creates its parent's), `findAsync` creates one on demand sharing a pending future, a sync `find` before that is a `StateError`, cycles are detected through a `Zone` chain (`_asyncChainKey`), and `Winter.start` awaits `di.ready()` before binding (a failure restores the registrations). `registrations` is a read-only snapshot (`DependencyRegistration`: `type`, `tag`, `kind` (`DependencyKind`), `created`) in registration order. `createAll()` (opt-in, before `Winter.start`) creates every lazy singleton not created yet, in registration order, logs each failure and throws one `StateError` naming all of them; factories and scoped ones are skipped. `disposeAll()` runs them in reverse registration order (only created instances) and clears everything; `Winter.shutdown()` calls it after `onShutdown`, `Winter.close()` doesn't. A registered `null` is valid: use `isRegistered` (not `tryFind != null`). Each instance has its own registrations. The global one is `di`, which lives in `Winter.context`.

## Tests

`test/integration/` runs every system together (`DECISIONS.md` §10): a whole app in memory, and the real server configured from `.env` files compared header by header with `WinterTestClient` (the real server sends no `X-Powered-By`). A change that touches several systems should keep both green.

Tests use `WinterTestClient` (`lib/src/testing/`): it runs the whole pipeline in memory, needs no port, and can run in parallel. Only the tests of the server itself start a real one (lifecycle, graceful shutdown, `dart:io` behavior in `test/server/http_server_behavior_test.dart`, start failures, DI registrations, `test/integration/server_integration_test.dart`): `setUpAll` starts it on a hard-coded port, and `tearDownAll` closes it. Test files run in parallel, so a new one needs a port that no other test file uses (grep `port` under `test/`). Branches nobody else covered are in `test/edge_cases_test.dart`. Mark server tests with `@TestOn('vm')`. Don't wait on the real clock in tests; inject a fake clock instead, as `RateLimiter(maxRequests:, window:, clock: ...)` does. Line coverage is about 99.7% (without the generated `*.g.dart`). The only uncovered lines are unreachable defensive code (a chain without a handler, a logger that throws outside the pipeline), races (a static file deleted between `stat` and resolving its links) branches of another platform (SIGTERM and Linux paths on Windows), the `onPause` of an SSE stream and a local time skipped by daylight saving. A test checks one thing that no other test checks: before adding one, grep for an existing test of the same behavior. A `List<int>` body of `WinterTestClient` is JSON, like in `ResponseEntity`; bytes are a `Uint8List`. Benchmarks live in `benchmark/`.
