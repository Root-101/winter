# i18n: the language of the request

Winter answers in the language of the client:

- The messages of its validators (`The field cannot be blank` / `El campo no puede estar vacío`).
- The texts of your app, with typed translations generated by [slang](https://pub.dev/packages/slang).
- `Vary: Accept-Language` is added by itself to every response that depends on the language.

By default there is only English, so an app doesn't change its responses until it opts in.

The decisions behind it are in [`DECISIONS.md` §1](../DECISIONS.md#1-translated-messages-i18n).

## Minimal example

```dart
import 'package:winter/winter.dart';

class Signup implements Validatable {
  final String? name;

  Signup(this.name);

  @override
  ConstraintValidatorContext validate() {
    final cvc = ConstraintValidatorContext();
    cvc.field('name', name).notBlank();
    return cvc;
  }
}

void main() async {
  Winter.context.setUp(
    localeConfig: LocaleConfig(supported: [WinterLocale.english, WinterLocale.spanish]),
    objectMapper: ObjectMapper(
      deserializers: [Deserializer<Signup>.json((json) => Signup(json['name'] as String?))],
    ),
  );

  await Winter.start(
    router: WinterRouter(
      routes: [
        Route.post(
          path: '/signup',
          handler: (request) async {
            await request.body<Signup>(); // validated: a 422 in the language of the request
            return ResponseEntity.created();
          },
        ),
      ],
    ),
  );
}
```

`POST /signup` with `{"name": ""}` and `Accept-Language: es-MX,es;q=0.9`:

```json
{
  "violations": [
    {"fieldName": "name", "message": "El campo no puede estar vacío", "code": "notBlank"}
  ],
  "type": "about:blank", "title": "Unprocessable Entity", "status": 422
}
```

The response has `Vary: Accept-Language`.

## How it works

### Enabling it

```dart
Winter.context.setUp(
  localeConfig: LocaleConfig(
    supported: [WinterLocale.english, WinterLocale.spanish], // by preference on a tie
    fallback: WinterLocale.english,                          // without a match
  ),
);
```

`WinterLocale('es')`, `WinterLocale('es', 'MX')` or `WinterLocale.tryParse('es-MX')` for any
language.

### How the language is chosen

From the `Accept-Language` of the request (RFC 9110): the languages from the highest `q` to the
lowest, `q=0` is "not acceptable", a region falls back to its language, and `fallback` when nothing
matches. With `supported: [en, es]`:

| `Accept-Language`              | Language |
|--------------------------------|----------|
| (none)                         | `en` (fallback) |
| `es`                           | `es`     |
| `es-MX`                        | `es` (the region falls back to its language) |
| `fr, es;q=0.8`                 | `es` (`fr` is not supported) |
| `es;q=0.5, en`                 | `en` (higher `q`) |
| `es;q=0, en;q=0.1`             | `en` (`q=0` is not acceptable) |
| `de`                           | `en` (fallback) |

### Reading the language

- `request.locale`: in a handler or a filter.
- `requestLocale`: from **any** code (a service, a validator, a repository), without receiving the
  request: every request runs in its own `Zone` (the `RequestScope`), so concurrent requests in
  different languages never mix. Outside a request it's the `fallback`.

### Winter's messages

The validators of Winter (`notNull`, `notBlank`, `size`, `min`, `max`, `email`, `pattern`, `url`,
`uuid`, `positive`..., the date ones) have texts in **English and Spanish**. Each violation also has
a `code` (`notBlank`, `size.max`) and `params`, so a client can translate them itself.

When the server starts, a supported language without Winter's messages (`fr`) logs a warning: its
validation messages are in English. To add a language to Winter, add
`lib/src/i18n/<language>.i18n.yaml` with the keys of `en.i18n.yaml`, run `fvm dart run slang` and
send a pull request.

### Translating the texts of your app with slang

As in [`example/04_i18n`](../example/04_i18n):

1. Add `slang` (and `intl`, imported by the generated code) to your `pubspec.yaml`.
2. Write the texts in YAML, nested, with typed parameters in the base language:

   ```yaml
   # lib/i18n/en.i18n.yaml
   orders:
     created: 'Order {id: int} created'
     notFound: 'Order {id: int} not found'
   ```

   ```yaml
   # lib/i18n/es.i18n.yaml
   orders:
     created: 'Pedido {id} creado'
     notFound: 'Pedido {id} no encontrado'
   ```

3. Configure slang like Winter does, in `slang.yaml`:

   ```yaml
   base_locale: en
   input_directory: lib/i18n
   input_file_pattern: .i18n.yaml
   output_directory: lib/i18n
   output_file_name: messages.g.dart
   string_interpolation: braces   # {id} like ARB/ICU
   fallback_strategy: none        # a missing key doesn't compile
   locale_handling: false         # no global locale: each request has its own
   flutter_integration: false
   class_name: AppMessages
   enum_name: AppLocale
   ```

4. Generate the code with `dart run slang`, and read the texts in the language of the request with
   a **getter**:

   ```dart
   final Map<AppLocale, AppMessages> _cache = {
     for (final l in AppLocale.values) l: l.buildSync(),
   };

   /// A getter, never a `final`: it's evaluated on every use, with the language of that request
   AppMessages get t => _cache[AppLocaleUtils.parseLocaleParts(
     languageCode: requestLocale.languageCode,
     countryCode: requestLocale.countryCode,
   )]!;
   ```

5. Use it anywhere: `throw NotFoundException(detail: t.orders.notFound(id: id))`, a response body,
   or the `message:` of a validator (`.notBlank(message: t.orders.productRequired)`).

### `Vary: Accept-Language`

Reading the language (`requestLocale` or `request.locale`) during a request marks it, and the server
adds `Vary: Accept-Language` to its response, merged with the `Vary: Origin` of CORS. It's only added
when the app supports more than one language. A response that never reads the language (a fixed
text, a 200 without texts) stays the same for every language, so a cache keeps one copy.

A validator only reads the language when it fails, so a valid request doesn't vary by language.

## Common cases

### Testing a translated response

```dart
final response = await client.post(
  '/signup',
  body: {'name': ''},
  headers: {'accept-language': 'es'},
);

expect((response.json as Map)['violations'][0]['message'], 'El campo no puede estar vacío');
expect(response.headers['vary'], contains('Accept-Language'));
```

### Testing a service without a server

```dart
RequestScope.run(RequestScope(locale: WinterLocale.spanish), () {
  expect(t.orders.notFound(id: 7), 'Pedido 7 no encontrado');
});
```

## Typical mistakes and limitations

- **`final t = ...`** or the validators in a `static final`: they keep the language of the first
  request. Build texts inside the request (a getter, `validate()`).
- **A language that Winter doesn't translate** (`fr`): your texts are in French, Winter's
  validation messages in English. The start warning lists them.
- Not translated on purpose: the `title` of a Problem Details and the reason phrase of the status
  line (standard HTTP texts), and the `detail` of a 400 of the object mapper (a technical message for
  the developer of the client).
